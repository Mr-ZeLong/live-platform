## 商品库存数据模型

商品库存数据模型 `SkuStockInfoPO` 是系统中管理商品库存的核心实体类，定义了SKU ID、库存数量、状态和版本号等关键字段，用于支持高并发场景下的库存管理。


**字段说明：**
- **skuId**: 商品唯一标识，与 `SkuInfoPO` 关联

- **version**: 乐观锁版本号，用于数据库更新时防止并发冲突


## 库存回滚机制

库存回滚通过消息队列实现，`StockRollbackConsumer` 监听订单关闭消息，将库存返还至Redis缓存。

```mermaid
sequenceDiagram
participant MQ as 消息队列
participant Consumer as StockRollbackConsumer
participant Service as SkuStockInfoServiceImpl
participant Redis
MQ->>Consumer : 发送回滚消息
Consumer->>Service : stockRollbackHandler()
Service->>Service : 查询订单状态
alt 订单未支付
Service->>Redis : increment() 增加库存
Redis-->>Service : 成功
Service-->>Consumer : 返回成功
else 订单已支付
Service-->>Consumer : 返回失败
end
```

## Redis Lua脚本保证原子性

系统使用Lua脚本确保库存扣减的原子性，避免高并发下的超卖问题。

```lua
-- Lua脚本逻辑
if (redis.call('exists',KEYS[1])) == 1 then 
    local currentStock=redis.call('get',KEYS[1])  
    if (tonumber(currentStock)>0 and tonumber(currentStock)-tonumber(ARGV[1])>=0) then 
        return redis.call('decrby',KEYS[1],tonumber(ARGV[1])) 
    else return -1 end 
else 
    return -1 end
```

**脚本说明：**
- 检查库存Key是否存在
- 验证当前库存是否足够
- 原子性执行 `decrby` 操作
- 返回-1表示扣减失败

## 分布式事务与消息队列解决方案

系统通过"缓存+数据库+消息队列"三级架构解决超卖问题：

```mermaid
flowchart TD
A[用户下单] --> B{Redis库存充足?}
B --> |是| C[扣减Redis库存]
C --> D[生成待支付订单]
D --> E[发送支付消息]
E --> F[支付服务]
F --> G{支付成功?}
G --> |是| H[确认订单]
G --> |否| I[发送回滚消息]
I --> J[StockRollbackConsumer]
J --> K[返还Redis库存]
K --> L[同步到数据库]
B --> |否| M[提示库存不足]
```

**核心机制：**
1. **预扣库存**：下单时扣减Redis库存，速度快
2. **异步持久化**：定时任务将Redis库存同步到数据库
3. **消息补偿**：支付失败时通过MQ触发库存回滚
4. **最终一致性**：保证库存数据最终一致

## 库存查询索引优化与分库分表策略

系统通过多级缓存和分库分表策略优化库存查询性能：

```mermaid
graph TB
A[客户端] --> B[Redis缓存]
B --> C{缓存命中?}
C --> |是| D[返回结果]
C --> |否| E[数据库查询]
E --> F[主库]
E --> G[从库]
F --> H[返回结果]
G --> H
H --> I[写入缓存]
J[分库分表] --> K[按anchorId分片]
K --> L[数据库1]
K --> M[数据库2]
K --> N[数据库n]
```

**优化策略：**
- **索引优化**：在 `t_sku_stock_info` 表的 `skuId` 字段建立唯一索引
- **分库分表**：按主播ID（anchorId）进行分片，降低单表数据量
- **缓存预热**：直播开始前通过 `prepareStockInfo` 接口预加载库存到Redis
- **定时同步**：通过 `RefreshSkuStockNumJob` 定时将Redis库存同步到数据库
