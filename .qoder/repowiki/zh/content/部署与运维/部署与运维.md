## 简介
本指南详细说明直播平台各微服务模块基于 Docker 与 docker-compose 的本地及生产环境部署流程。涵盖镜像构建、服务编排、配置中心集成、日志管理、监控接入等核心运维内容，为系统稳定运行提供保障。

## Docker 镜像构建策略

### 基础镜像选择
所有服务均采用 `docker.xuanyuan.dev/openjdk:17-jdk-alpine` 作为基础镜像。该镜像基于 Alpine Linux，具有体积小、安全性高的特点，同时预装 OpenJDK 17，满足 Spring Boot 3.x 应用运行需求。

### JAR 包复制与启动命令
Dockerfile 中通过 `ADD` 指令将构建好的 JAR 包（如 `app.jar`）复制到容器根目录。通过 `ENV` 定义 `JAVA_OPTS` 环境变量设置 JVM 参数，并在 `ENTRYPOINT` 中调用 `java -jar` 启动应用。

JVM 参数包含：
- `-server`：启用 Server 模式 JVM
- 内存设置（如 `-Xms512m -Xmx512m`）
- 模块化访问权限开放（`--add-opens`），解决 JDK 9+ 模块系统带来的反射访问限制
- `-Djava.security.egd=file:/dev/./urandom`：加速应用启动时的随机数生成

## Docker Compose 服务编排

### 服务定义与端口映射
`docker-compose.yml` 文件定义了各服务的容器名称、镜像、端口映射、数据卷挂载、环境变量和主机映射。

- **端口映射**：将容器内服务端口映射到宿主机，如 `live-api` 服务将 8081 端口映射到宿主机 8081 端口。
- **数据卷挂载**：将容器内日志目录（如 `/tmp/logs/live-api`）挂载到宿主机对应路径，实现日志持久化。
- **环境变量注入**：通过 `environment` 字段注入关键配置，如时区 `TZ`、JVM 参数 `JAVA_OPTS`、Dubbo 注册 IP 和端口等。

### 网络配置与依赖关系
- **extra_hosts**：通过 `extra_hosts` 配置将 `live-server` 域名映射到指定 IP 地址（如 `192.168.0.254`），确保服务能正确访问 Nacos 配置中心和注册中心。
- **服务依赖**：虽然未显式使用 `depends_on`，但通过 `extra_hosts` 和环境变量的配置，隐式建立了服务对 Nacos 服务器的依赖关系。

部分服务（如 `live-api` 和 `live-user-provider`）配置了多个实例，实现本地环境的负载均衡测试。

## Nacos 配置管理

### bootstrap.yml 配置解析
`bootstrap.yml` 是应用启动时最先加载的配置文件，用于连接 Nacos 配置中心。

核心配置项：
- **服务名称**：`spring.application.name` 定义服务在 Nacos 中的唯一标识。
- **Nacos 认证**：`spring.cloud.nacos.username` 和 `password` 提供访问 Nacos 的凭据。
- **发现配置**：`spring.cloud.nacos.discovery.server-addr` 指定 Nacos 服务器地址和端口，`namespace` 指定命名空间，用于环境隔离。
- **配置管理**：`spring.cloud.nacos.config` 下的 `server-addr` 和 `namespace` 与发现配置保持一致，`file-extension` 指定配置文件格式为 `yaml`。
- **配置导入**：`spring.config.import` 使用 `optional:nacos:` 语法，声明从 Nacos 动态加载与服务名同名的 YAML 配置文件。

## 日志管理方案

### Logback 配置策略
`logback-spring.xml` 文件定义了统一的日志输出格式、滚动策略和存储位置。

- **日志路径**：`LOG_HOME` 被设置为 `/tmp/logs/${APP_NAME}/${index}`，其中 `${APP_NAME}` 由 `spring.application.name` 动态获取，`${index}` 通过自定义类 `IpLogConversionRule` 生成，防止多容器日志目录冲突。
- **输出格式**：`LOG_PATTERN` 定义了包含时间、日志级别、类名和消息的标准化格式。
- **日志滚动**：使用 `TimeBasedRollingPolicy` 按天滚动日志文件，`maxHistory` 设置为 1，保留最近一个月的日志。
- **多级输出**：
  - `CONSOLE`：控制台输出所有 INFO 及以上级别日志。
  - `INFO_FILE`：文件输出所有日志。
  - `ERROR_FILE`：文件单独输出 ERROR 级别日志，并通过 `LevelFilter` 过滤非错误日志。

## 健康检查与监控

### 健康检查路径

## 扩缩容策略

### 水平扩展
通过 `docker-compose.yml` 文件可以轻松实现服务的水平扩展。例如，`live-api` 服务定义了 `live-api-docker-1` 和 `live-api-docker-2` 两个实例，分别监听宿主机的 8081 和 8082 端口。在生产环境中，可结合 Kubernetes 或 Docker Swarm 等编排工具，根据 CPU、内存等指标自动调整实例数量。

### 资源配置
各服务的 `docker-compose.yml` 文件通过 `JAVA_OPTS` 环境变量精确控制 JVM 内存（如 `-Xms512m -Xmx512m`），确保单个实例的资源消耗可控，为扩缩容提供稳定的基础。

## 常见问题排查清单

### 服务注册失败
- **检查网络连通性**：确认服务容器能通过 `extra_hosts` 映射的 `live-server` 域名访问 Nacos 服务器（8848 端口）。
- **验证认证信息**：检查 `bootstrap.yml` 中的 `username` 和 `password` 是否与 Nacos 服务器配置一致。
- **核对命名空间**：确认 `namespace` 配置正确，且该命名空间在 Nacos 中已创建。
- **查看日志**：检查服务日志中是否有 `Failed to register` 或 `Connection refused` 等错误信息。

### 配置未生效
- **检查配置文件名**：确保 Nacos 配置中心中配置文件的 Data ID 与 `spring.application.name` 完全一致。
- **确认配置格式**：检查 Nacos 中配置的格式（YAML）是否与 `file-extension` 设置匹配。
- **验证配置内容**：检查 Nacos 中的配置内容是否正确，特别是 YAML 的缩进和语法。
- **重启服务**：某些配置需要重启服务才能生效。

### 日志文件未生成
- **检查挂载路径**：确认 `docker-compose.yml` 中的 `volumes` 配置正确，宿主机路径可写。
- **验证日志路径**：检查容器内 `/tmp/logs` 目录是否存在且有写入权限。
- **查看应用日志**：检查控制台输出，确认 Logback 是否成功初始化，有无 `File not found` 或 `Permission denied` 错误。
